# Microsoft Writing Style Guide: adopted rules

## Purpose

The Microsoft Writing Style Guide is the primary editorial authority for this
skill: terminology, mechanics, voice, and instructions. This file records what
was adopted, how it was adapted, and where to look up the rest. It isn't a copy
of the guide. The decision register carries each adopted rule in operational
form, so a draft never needs the guide itself.

## Source

- Guide: <https://learn.microsoft.com/style-guide/welcome/>
- Reviewed against the November 7, 2026, Learn export (content through
  Microsoft's October 30, 2026, updates). Greg keeps the dated PDF export in
  the Deliverable Accelerator's `StyleGuides` folder. It's too large to bundle.
- Microsoft updates the guide continuously. Before relying on a rule for an
  edge case, check the live page.

## Adopted

| Area | What the register takes | Register section |
| --- | --- | --- |
| Capitalization | Sentence case for headings, labels, list items, and captions; official names exactly as written | 2, 3 |
| Punctuation | Serial comma, colons, semicolons, quotation marks, list punctuation, and hyphens; no exclamation points or ampersands | 2, 3 |
| Numbers, dates, and times | Words for zero through nine; numerals for 10 and up, measurements, and versions; "Month D, YYYY"; "10:00 AM" | 3 |
| Contractions | Common contractions by default | 3 |
| Acronyms | Spell out on first use unless the audience knows the acronym better | 3 |
| Voice and person | "You" and the imperative in instructions; active voice; present tense | 4 |
| Word list | Latin abbreviations, filler, sign in, set up, email, on-premises, select, clear, run, dialog box, pane, and allow list and block list | 2, 4 |
| Bias-free communication | Gender-neutral and people-first language; no "master/slave" or "whitelist/blacklist" | 2, 4 |
| Global communications | Literal language, no idioms, unambiguous dates | 4 |
| Procedures and instructions | Numbered steps, location before action, input-neutral verbs, bold UI labels, ">" sequences, prepositions by element | 6 |
| Formatting text elements | Code formatting for what the reader types or matches; bold only for UI labels and run-in labels | 5, 7 |

Recent changes already reflected, from the Deliverable Accelerator's
November 24, 2026, review:

- **Dialog box** is the preferred term again. Microsoft reversed its earlier
  rule on October 30, 2026.
- **Allow list and block list** are two words (January 15, 2026).
- **A portal pane is a pane**, not a blade (March 6, 2026). Hardware blades are
  unaffected.
- **Permissions and privileges** aren't synonyms, and neither is a role, access,
  an identity, or a service principal.

## Adapted

| Microsoft rule | House adaptation | Why |
| --- | --- | --- |
| Em dashes are allowed (closed, no spaces) | No em dashes at all | Greg's standing preference: colons, parentheses, commas, or a new sentence instead |
| Titles use sentence case | A document's title uses title case; headings stay sentence case | Greg's template decision for the document title block |
| Placeholders stand for user-supplied values | Real environment values first; placeholders only for unknown values | Greg's standing preference for implementation guides |

## Not adopted

- Rules specific to Microsoft's own web publishing: article date stamps,
  feedback blocks, and expandable tables.
- Microsoft's brand voice beyond the shared principles (clear, warm, and
  direct).
- A readability grade target.
